การตรวจโค้ดพบว่าการส่งแบบเดิมแสดง fetch error ตรง ๆ และยังเปิดให้เปลี่ยนรายการหลังคำตอบขาดหาย จึงเสี่ยงสร้างคำขอใหม่ทั้งที่บิลแรกอาจบันทึกแล้ว การแก้ครั้งนี้รับมือสถานการณ์ดังกล่าว ไม่ได้พิสูจน์ว่าหาสาเหตุเครือข่ายของ “Load failed” บนมือถือได้ทั้งหมด

การตรวจอัตโนมัติประกอบด้วย strict TypeScript ทั้ง frontend/Edge, lint, production build, HTML preview, **36 Node/PGlite tests** และ **16 Chromium scenarios** รวมจำลองการตัดการเชื่อมต่อหลัง POST, ส่งซ้ำรหัสเดิม, เก็บรายการค้างหลัง reload, ปลดล็อกเมื่อ server ปฏิเสธราคาแน่นอน, เปลี่ยนชื่อเมนู และรักษาบิลเก่า ชุด Chromium ใช้ API จำลอง; หลังแก้ error handling ได้รันซ้ำชุดเมนู/ส่งออเดอร์ที่เกี่ยวข้องครบ 7 เคสผ่าน โดยอีก 9 เคสผ่านในการรันเต็มก่อนหน้า

Migration ตรวจบน PGlite ก่อนลงจริง และตรวจ snapshot ของบิลที่มีอยู่ก่อนอัปเดตแล้วไม่เปลี่ยน ไม่ได้ล้างบิลหรือทับเมนูที่ Owner สร้างเอง

## ขอบเขตที่ยังต้องทดสอบจริง

รอบนี้ยืนยันการรับออเดอร์พร้อมกันและการส่งซ้ำผ่าน API ไม่ได้จำลองการกดบนมือถือ 8 เครื่อง จึงยังไม่ยืนยันว่า iPhone จะไม่ค้าง, Realtime จะปรากฏบนจอครัวทันที, การติดตั้ง PWA/offline ใช้งานได้ครบ หรือระบบรองรับช่วงเที่ยงต่อเนื่องได้เท่าใด

เปิดครัว/POS บนเครื่องร้านแล้วตรวจ 8 บิลทดสอบ จากนั้นทดสอบมือถือจริง: ส่งรายการพร้อมโน้ต, เปลี่ยนสถานะที่ครัว, ให้ลูกค้าเห็นสถานะ, กลับบ้าน/ส่งหมู่บ้าน และการเปลี่ยนชื่อเมนู ดู [ขั้นตอนตรวจรับ](../acceptance-tests.md)

**สถานะหลังทดสอบ:** เก็บบิลทดสอบทั้ง 8 ไว้ให้ตรวจ ยังไม่ได้รับเงินหรือยกเลิก หลังตรวจแล้วให้ยกเลิกผ่านขั้นตอนปกติของร้าน อย่ารับเงินบิลทดสอบเป็นยอดขายจริง

## รันสคริปต์ซ้ำเมื่อได้รับอนุญาตให้สร้างบิลทดสอบ

ใช้ Node 24 จากโฟลเดอร์รากของ repo ค่าเหล่านี้เป็นตัวแปรเฉพาะสคริปต์ ไม่ใช่ environment ใหม่ของแอป:

```sh
TABLE_TEST_BASE_URL=https://YOUR_PROJECT.supabase.co TABLE_TEST_ORIGIN=https://YOUR_SITE.pages.dev node scripts/test-all-tables.mjs prepare
```

สคริปต์สร้าง `.local-data/table-tests/<runId>/private.json` และ `bootstrap.sql` แบบ private โดยยังไม่ส่งบิล ตรวจ SQL แล้วรันใน project เดียวกันด้วยผู้ดูแลเพื่อสร้าง session ครบ 8 โต๊ะ ต้องมี QR ที่ใช้งานอยู่สำหรับทุกโต๊ะอยู่แล้ว ห้ามเผยแพร่ไฟล์ private หรือค่าของ token

```sh
TABLE_TEST_ALLOW_WRITE=EIGHT_TABLES_AUTHORIZED node scripts/test-all-tables.mjs run .local-data/table-tests/<runId>/private.json
```

ใช้ private file เดิมเมื่อจะลองส่งชุดเดิมซ้ำ เพราะ `prepare` ใหม่จะสร้างรหัสใหม่และทำให้เกิดบิลทดสอบเพิ่ม ไม่มีการรับเงิน ยกเลิกบิล หรือวนโหลดต่อเนื่องในสคริปต์ ผล `report.json` อยู่ข้าง private file; ตรวจและลบตัวระบุก่อนนำไปเผยแพร่ ใน Cloud ที่กำหนด HTTPS proxy/CA ใช้ Node flags `--use-env-proxy --use-system-ca`; ห้ามปิดการตรวจ TLS
