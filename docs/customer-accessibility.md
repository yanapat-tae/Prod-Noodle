# หน้าลูกค้า: อ่านง่ายและแตะง่ายเป็นค่าเริ่มต้น

ข้อกำหนดนี้ใช้กับหน้าสแกน QR เมนู ตัวเลือก ตะกร้า และติดตามออเดอร์ โดยคำนึงถึงผู้สูงอายุ ไม่ต้องให้ผู้ใช้เปิดโหมดพิเศษก่อนจึงจะอ่านได้ รุ่นทดลองทุกเมนูแสดง emoji 🍜 แทนภาพ และยังไม่โหลดรูปอาหาร

## ขนาดและความชัดเจน

| รายการ | ค่าเริ่มต้นที่ใช้พัฒนา |
|---|---|
| ตัวอักษรหลัก / ตัวเลือก / ปุ่ม | 1.25rem หรือประมาณ 20px เมื่อ browser ตั้งไว้ 16px |
| ชื่อเมนู / ราคา | 1.5–1.75rem หรือประมาณ 24–28px |
| ข้อความประกอบ | อย่างน้อย 1.125rem หรือประมาณ 18px |
| ระยะบรรทัดภาษาไทย | 1.65 เพื่อไม่บีบสระและวรรณยุกต์ |
| พื้นที่กดปุ่ม / ตัวเลือก / เพิ่มลดจำนวน | อย่างน้อย 56 × 56 CSS px; ตัวเลือกยาวขยายสูงตามข้อความ |
| ช่องว่างระหว่างพื้นที่กด | อย่างน้อย 12px |
| สีตัวหนังสือ | สีเข้มบนพื้นอ่อน ตั้งเป้า contrast อย่างน้อย 7:1 สำหรับข้อความหลัก |
| จำนวนคอลัมน์มือถือ | หนึ่งคอลัมน์ ไม่ย่อชื่อ/ตัวเลือกให้พอดีหลายคอลัมน์ |

ขนาดข้างต้นเป็นการเลือกออกแบบสำหรับร้านนี้ WCAG 2.2 AA กำหนด target ขั้นต่ำ 24 × 24 CSS px พร้อมข้อยกเว้น แต่ปุ่มใหญ่กว่านั้นช่วยผู้ที่กดตำแหน่งเล็กได้ยาก ตาม [W3C Target Size](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html) ใช้ rem เพื่อเคารพขนาดตัวอักษรที่ตั้งใน browser และรองรับขยายข้อความ 200% ตาม [W3C Resize Text](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html) ข้อความทั่วไปต้องมี contrast อย่างน้อย 4.5:1 ตาม [W3C Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html) เป้าหมาย 7:1 ของร้านเป็นค่าที่เลือกให้ชัดขึ้น

## เมนูและการเลือกอาหาร

- แสดง “โต๊ะ 3” หรือ “สั่งกลับบ้าน” ชัดเจนตั้งแต่สแกน ห้ามให้พิมพ์เลขโต๊ะซ้ำ
- ทุกเมนูใช้ 🍜 เป็นภาพตกแต่ง (`aria-hidden="true"`) ชื่ออาหารและราคาต้องเป็นข้อความจริง ไม่ใช้ emoji แทนชื่อ รวมถึงเครื่องดื่ม/ของหวานตามข้อกำหนดรุ่นทดลอง
- ใช้ font ไทยที่มีอยู่ในเครื่องและน้ำหนักปกติ/หนา หลีกเลี่ยงตัวบาง ลายมือ และบริการ font เพิ่มเติมในรุ่นทดลอง ทดสอบอ่านภาษาไทยบน iPhone และ Android จริง
- ชื่อเมนูแสดงครบและขึ้นบรรทัดใหม่ได้ ไม่ทำ ellipsis และไม่บังคับความสูงการ์ดจนตัดตัวหนังสือ
- ปุ่มใช้คำชัดเจน เช่น “เลือกเมนูนี้”, “เพิ่มลงตะกร้า”, “ดูตะกร้า”, “ยืนยันส่งออเดอร์” มีข้อความคู่กับสัญลักษณ์
- เส้น/ขนาดใช้ native radio พร้อม label แถวใหญ่ที่แตะได้ทั้งแถว ส่วน topping ใช้ checkbox แถวใหญ่ จัดกลุ่มด้วย fieldset/legend และระบุ “เลือก 1 อย่าง” หรือ “เลือกเพิ่มได้”
- ตัวเลือกที่เลือกแล้วมีกรอบ/เครื่องหมายและคำ “เลือกแล้ว” ไม่ใช้แค่การเปลี่ยนสี ถ้าขนาดมี default ต้องแสดงให้เห็นและแก้ได้ ไม่เลือกเส้นแทนผู้ใช้หากร้านไม่ได้กำหนด default
- แสดงค่าบวกเพิ่มเป็น “มาม่า +5 บาท” และยอดปัจจุบัน ไม่ใช้ตัวอักษรเล็กไว้หลังชื่อ
- ปุ่มเพิ่ม/ลดจำนวนขนาดใหญ่ และแสดง “จำนวน 1 ชาม” มี accessible name เช่น “เพิ่มจำนวน” ไม่บังคับกรอกช่องตัวเลข
- เปิดหน้าตัวเลือกแบบเต็มหน้าจอบนมือถือ เพื่อให้พื้นที่พอและอ่านได้ ใช้ปุ่ม “กลับไปเลือกเมนู” ที่เห็นชัด ไม่มีการบังคับ swipe หรือแตะปิดที่พื้นที่ว่าง

## ตะกร้าและการยืนยัน

- ปุ่มดูตะกร้าแสดง “ดูตะกร้า · 2 รายการ · 110 บาท” ถ้าปุ่ม sticky ต้องเพิ่มพื้นที่ท้ายรายการและ safe-area ไม่บังปุ่มสุดท้าย
- หน้ารีวิวแสดงชื่ออาหาร เส้น ขนาด topping จำนวน และยอดเต็ม อ่านแล้วแก้ไขได้ก่อนส่ง
- หลังแตะส่ง แสดง “กำลังส่งออเดอร์” แล้วรอ server ACK จึงแสดง “ร้านรับออเดอร์แล้ว” ปุ่มไม่รับการกดซ้ำขณะส่ง
- เมื่อข้อมูลขาด แสดงใกล้กลุ่มที่ต้องเลือก เช่น “กรุณาเลือกเส้นก่อน” ไม่ใช่ alert ภาษาเทคนิค และย้าย focus ไปกลุ่มนั้น
- เน็ตขาดต้องบอก “ยังส่งไม่สำเร็จ กรุณาลองอีกครั้ง” และรักษาตะกร้าไว้ ไม่ล้างรายการทิ้ง
- ไม่มีการบังคับสมัครสมาชิก ใช้เสียง หรือกดติดตั้ง PWA เพื่อสั่งอาหาร

## การขยายและเครื่องมือช่วยอ่าน

ใช้ viewport `width=device-width, initial-scale=1` โดยไม่ใส่ user-scalable=no หรือ maximum-scale ที่ขวางการซูม ไม่ปิด pinch-to-zoom และไม่ปิด text scaling ปุ่มมี min-height แทน fixed height เมื่อขยายตัวหนังสือ ข้อความปุ่มและตัวเลือกต้อง wrap ได้

ใช้ native button/input, focus ring ที่มองเห็น, label ครบ และประกาศสถานะเพิ่มตะกร้า/ส่งออเดอร์ผ่าน aria-live แบบสุภาพ ไม่ประกาศราคาและสถานะซ้ำทุกครั้งที่ poll เคารพ prefers-reduced-motion

เชื่อม CSS `src/styles/customer-accessibility.css` กับ React แล้ว ใช้ rem และปุ่ม native ตรวจจอ 320px ใน browser แล้วตาม docs/validation.md ยังต้องทดสอบ text zoom/อุปกรณ์จริงและผู้สูงอายุก่อนสรุปว่าแอปผ่าน accessibility

## เกณฑ์ทดสอบก่อนนำไปลองในร้าน

ทดสอบความกว้าง 320/375/390 CSS px, ตัวอักษร browser ขยาย และ zoom 200% ชื่ออาหาร/ราคาต้องไม่ถูกตัด ต้องไม่มีการเลื่อนแนวนอนเพื่ออ่านรายการ ตัวเลือกและปุ่มสุดท้ายไม่ถูกแถบตะกร้าบัง ทดสอบเมนูชื่อยาวและราคา topping จริง รวมทั้ง keyboard/VoiceOver/TalkBack เพื่อยืนยัน label และ focus

ให้ผู้สูงอายุประมาณ 3–5 คนลองสแกน เลือกอาหาร เลือกเส้น เพิ่มจำนวน ตรวจตะกร้า และส่งออเดอร์ด้วยตนเอง บันทึกจุดอ่านไม่ออก/กดผิด/ต้องขอความช่วยเหลือ แล้วปรับก่อนเพิ่มรูปหรือเสียง จำนวนคนเป็นแผนทดลอง ไม่ใช่การทดสอบที่ทำไปแล้ว
